# Client API Reference

The Convex CMS client provides a typed wrapper around the component's raw functions. This document covers the complete API.

> For Admin UI backend functions, see [Admin API Reference](./admin-api.md). For integration guidance, see [Integration Patterns](../guides/integration-patterns.md).

---

## Creating the Client

```typescript
import { createCmsClient } from "convex-cms";
import { components } from "./_generated/api";

const cms = createCmsClient(components.convexCms, config);
```

See [Configuration Reference](./configuration.md) for all available options.

## API Namespaces

The client organizes methods into namespaces:

- `cms.contentTypes` - Content type operations
- `cms.contentEntries` - Entry operations (includes query builder)
- `cms.versions` - Version history
- `cms.mediaAssets` - Media files (stored in `mediaItems` table with `kind: "asset"`)
- `cms.mediaFolders` - Folder organization (stored in `mediaItems` table with `kind: "folder"`)
- `cms.mediaVariants` - Image variants
- `cms.locale` - Locale configuration and resolution

> **Note**: Taxonomy and content locking operations are available via the Admin API (`defineAdminAPI`). See [Admin API Reference](./admin-api.md).

## Types

> **ID types at the component boundary**: All IDs returned from or passed to the CMS client are `string`, not `Id<"...">`. The component uses `StringifyIds<T>` internally to convert all Convex document IDs to plain strings when crossing the component boundary. This applies to `_id`, `parentId`, `primaryEntryId`, `entryId`, `assetId`, `storageId`, and all other ID fields.

### FieldDefinition

Every field definition requires `name`, `label`, `type`, and `required`. The `label` property is required for all field types.

```typescript
interface FieldDefinition {
  name: string;
  label: string;
  type: "text" | "richText" | "number" | "boolean" | "date" | "datetime"
      | "reference" | "media" | "json" | "select" | "multiSelect" | "tags" | "category";
  required: boolean;
  searchable?: boolean;
  localized?: boolean;
  description?: string;
  defaultValue?: any;
  options?: FieldOptions;  // Type-specific options
}
```

Media field options use `allowedMimeTypes` (not `allowedTypes`), `maxFileSize` (not `maxSize`), and `mediaType`:

```typescript
// Media field options
{
  mediaType?: "image" | "video" | "audio" | "document" | "other";
  allowedMimeTypes?: string[];
  maxFileSize?: number;
  multiple?: boolean;
  maxItems?: number;
}
```

### PaginationResult

All `list` methods return this format:

```typescript
interface PaginationResult<T> {
  page: T[];
  continueCursor: string | null;
  isDone: boolean;
}
```

### PaginationOpts

```typescript
interface PaginationOpts {
  numItems: number;
  cursor: string | null;  // null for first page
}
```

## Content Types API

### create

Create a new content type.

```typescript
const type = await cms.contentTypes.create(ctx, {
  name: string;               // Unique identifier
  displayName: string;        // Human-readable name
  createdBy: string;          // Creator user ID (REQUIRED)
  description?: string;
  fields: FieldDefinition[];  // Field definitions (each requires `label`)
  icon?: string;
  singleton?: boolean;
  slugField?: string;
  titleField?: string;
  sortOrder?: number;
});
```

### update

Update an existing content type.

```typescript
const result = await cms.contentTypes.update(ctx, {
  id: string;
  displayName?: string;
  description?: string;
  fields?: FieldDefinition[];
  icon?: string;
  singleton?: boolean;
  slugField?: string;
  titleField?: string;
  sortOrder?: number;
  isActive?: boolean;
  updatedBy?: string;
  force?: boolean;            // Force update even with breaking changes
});
// Returns ContentType & { breakingChanges?: BreakingChange[] }
```

Returns `breakingChanges` array if updates would break existing content.

### delete

Delete a content type.

```typescript
await cms.contentTypes.delete(ctx, {
  id: string;
  cascade?: boolean;      // Delete related entries
  hardDelete?: boolean;   // Permanent deletion
  deletedBy?: string;
});
// Returns: { success, deletedId, deletedEntriesCount, deletedVersionsCount, wasHardDelete }
```

### get

Get a content type by ID or name.

```typescript
const type = await cms.contentTypes.get(ctx, {
  id?: string;
  name?: string;
  includeDeleted?: boolean;
});
// Returns: ContentType | null
```

### getByName

Get a content type by name.

```typescript
const type = await cms.contentTypes.getByName(ctx, name, includeDeleted?);
// Returns: ContentType | null
```

### getById

Get a content type by ID.

```typescript
const type = await cms.contentTypes.getById(ctx, id, includeDeleted?);
// Returns: ContentType | null
```

### exists

Check if a content type exists by name.

```typescript
const exists = await cms.contentTypes.exists(ctx, name, includeDeleted?);
// Returns: boolean
```

### list

List content types with pagination.

```typescript
const result = await cms.contentTypes.list(ctx, {
  isActive?: boolean;
  includeDeleted?: boolean;
  sortBy?: "name" | "createdAt";
  sortDirection?: "asc" | "desc";
  paginationOpts?: PaginationOpts;
});
// Returns: PaginationResult<ContentType>
```

### listActive

List only active content types.

```typescript
const result = await cms.contentTypes.listActive(ctx, paginationOpts?);
// Returns: PaginationResult<ContentType>
```

### count

Get the count of content types.

```typescript

  isActive?: boolean;
  includeDeleted?: boolean;
});
// Returns: number
```

### deactivate

Deactivate a content type (sets `isActive` to false).

```typescript

```

### reactivate

Reactivate a deactivated content type (sets `isActive` to true).

```typescript

```

### Query Builder

```typescript

const owns = cms.isOwner(userId, resourceOwnerId);
```
