  <project_name>convex-cms</project_name>

  <overview>
    A developer-first Convex Component for content management with a built-in React admin playground, flexible RBAC, and AI-ready architecture. This headless CMS runs entirely within a Convex backend, providing content modeling, versioning, publishing workflows, and media management through a sandboxed component architecture with isolated database tables and type-safe APIs.

The component is designed for seamless integration with the Convex AI ecosystem - including @convex-dev/agent for AI-powered content operations, @convex-dev/rag for semantic search and retrieval-augmented generation, and collaborative editing components for real-time multi-user content authoring. By leveraging Convex&apos;s component architecture, it maintains strict API boundaries while enabling powerful composition with other Convex components.

Key architectural goals:
- Provide a complete headless CMS as a drop-in Convex component
- Include a batteries-included Admin UI built with React and TanStack Start
- Offer flexible RBAC with sensible defaults and customization hooks
- Enable AI agents to create, query, and manage content programmatically through tool integrations
- Support content retrieval for RAG pipelines with structured content chunks
- Maintain real-time reactivity across all content queries
- Design for AI-assisted development with clean, predictable patterns
- Expose webhook/event systems for external AI pipeline integrations
  </overview>

    <capability>Slug Management - Automatic URL-safe slug generation with uniqueness validation per content type</capability>
    <capability>Content Relations - Reference other content entries and media assets with typed relationships and depth-limited resolution</capability>

  <additional_requirements>
    <requirement>Convex deployment required for backend hosting (convex.dev)</requirement>
    <requirement>Parent application must handle authentication and pass user identifiers explicitly to component functions (ctx.auth unavailable in components)</requirement>
    <requirement>Media uploads use Convex file storage (subject to Convex storage limits and pricing)</requirement>
    <requirement>Environment variables must be passed as function arguments, not accessed via process.env inside component</requirement>
    <requirement>Use convex-helpers paginator instead of built-in .paginate() for pagination within components</requirement>
    <requirement>Content queries are reactive by default - consider caching strategies for high-traffic scenarios</requirement>
    <requirement>Component isolation means no direct database access from parent - all operations through typed API functions</requirement>
    <requirement>Function handles required for callback patterns (authorization hooks, event handlers)</requirement>
    <requirement>For AI integration: Component APIs should be designed as tools for @convex-dev/agent consumption</requirement>
    <requirement>For RAG integration: Content should be structurable as chunks with metadata for @convex-dev/rag indexing</requirement>
  </additional_requirements>

  <development_guidelines>
    <guideline>All public component functions must have explicit argument and return validators using Convex v.* validators</guideline>
    <guideline>Export ComponentApi type from _generated/component.js for type-safe client usage</guideline>
    <guideline>Pass userId or auth context explicitly to component functions rather than relying on ctx.auth</guideline>
    <guideline>Use function handles (createFunctionHandle) for callback patterns where parent app provides custom logic</guideline>
    <guideline>Provide test helpers in src/test.ts for convex-test registration pattern</guideline>
    <guideline>Maintain backwards compatibility when updating - component state persists across version updates</guideline>
    <guideline>Document all public functions with JSDoc comments for better developer experience</guideline>
    <guideline>Use sub-transactions appropriately - each component mutation call is isolated and can be caught/handled</guideline>
    <guideline>HTTP actions must be mounted by parent app in convex/http.ts - component cannot expose routes directly</guideline>
    <guideline>Design APIs to be AI-agent friendly: clear parameter names, predictable return shapes, tool-compatible signatures</guideline>
    <guideline>Structure content retrieval for RAG: support chunk extraction, metadata tagging, and embedding-friendly formats</guideline>
  </development_guidelines>
